# CONTRIBUTING.md

Welcome to the Al-Haqq Protocol and Inverted Pyramid Framework. This document guides how you can contribute meaningfully to this work.

---

## Our Principles

Before contributing, understand that this framework is built on:

1. **Al-Haqq (Absolute Truth)**: We're committed to truth over comfort, facts over narratives
2. **Inverted Pyramid**: Wisdom comes from those closest to problems, not distant from them
3. **ICAM**: We collaborate across different ways of knowing (human, AI, diverse perspectives)
4. **Intellectual Humility**: We know we're wrong about some things; your job is helping us find what

---

## Ways to Contribute

### 1. Strengthen the Documentation

**What we need:**
- Expand explanations that aren't clear
- Add historical examples or research citations
- Identify logical gaps
- Suggest better framings

**How to do it:**
1. Create an issue: "The section on [X] is unclear because [Y]"
2. Propose improvement: "What if we framed it as [new framing]?"
3. Submit a pull request with changes
4. Engage in discussion about the changes

**Quality standards:**
- Changes preserve the core logic
- New content is evidence-based or clearly marked as exploratory
- Language is clear and accessible
- Consistency with other sections is maintained

### 2. Add Real-World Case Studies

**What we need:**
- Organizations implementing the framework
- Individuals practicing the principles
- Communities using the methodology
- Documented successes AND failures

**Case study template:**
See `CASE-STUDY-TEMPLATE.md` in this repo

**How to do it:**
1. Implement the framework (or identify an implementation)
2. Document the journey with the template
3. Submit as pull request to `/case-studies/` directory
4. Community discusses and validates

**What makes a great case study:**
- Honest about what worked and what didn't
- Includes quantitative and qualitative data
- Identifies specific challenges and how you addressed them
- Provides advice for others attempting similar work
- Acknowledges limitations and context

### 3. Challenge Our Assumptions

**What we need:**
- Serious critique of our logic
- Counter-examples that break our framework
- Blind spots we haven't noticed
- Ethical concerns about how this could be misused

**How to do it:**
1. Open a discussion: "I think your logic on [X] has this problem: [Y]"
2. Be specific: Point to the exact claim you're challenging
3. Provide evidence: Show where the framework fails
4. Suggest direction: "Have you considered [alternative]?"

**Community standards:**
- Criticism is intellectual, not personal
- You're genuinely trying to improve the framework, not just prove it wrong
- You've understood the position before critiquing it
- You're open to the possibility that the framework addresses your concern in ways you haven't seen

### 4. Develop Implementation Tools

**What we need:**
- Decision-making templates based on the framework
- Assessment tools for organizations
- Training materials
- Technology that helps people practice the principles

**How to do it:**
1. Propose the tool in an issue: "I'm developing [X tool] because [Y reason]"
2. Get feedback from community
3. Build it in a separate branch
4. Submit for integration when ready
5. Document how to use it

**Quality standards:**
- Faithful to the core principles
- Actually useful for practitioners
- Well-documented
- Tested with real users

### 5. Translate & Localize

**What we need:**
- Translations to other languages
- Adaptations for different cultural contexts
- Consideration of how principles apply differently in different places
- Validation that translations preserve meaning

**How to do it:**
1. Check if someone is already translating to your language (Issues/Discussions)
2. Coordinate with them to avoid duplication
3. Translate with attention to meaning, not just words
4. Submit translations in `/translations/[language]/` directory
5. Engage native speakers for validation

**Quality standards:**
- Accuracy: Does it mean the same thing in the target language?
- Accessibility: Is the language clear and natural?
- Cultural sensitivity: Does it work in this cultural context?
- Completeness: All materials translated together, not piecemeal

### 6. Connect Across Domains

**What we need:**
- Connections to other frameworks, research, or movements
- Literature that validates or challenges our thinking
- Examples from unexpected fields where similar principles appear
- Research that tests the framework

**How to do it:**
1. Open a discussion: "This framework connects to [X field/research/movement] in these ways: [Y]"
2. Provide specific links and citations
3. Explain the connection
4. Suggest implications for our framework

**Community standards:**
- Connections are substantive, not superficial
- You've actually engaged with the other framework/research
- You acknowledge where they differ from ours, not just similarities
- Implications are thoughtful, not just promotional

## Process for Contributing

### Small Changes (Documentation fixes, clarifications)

1. Create a pull request directly
2. Title describes the change: "docs: Clarify Al-Haqq definition"
3. Description explains why: "The existing text was unclear about [X]; this change [Y]"
4. Community members review
5. If no objections in 48 hours, merge

### Medium Changes (New case studies, new sections, new tools)

1. Open an issue first: "I want to add [X] because [Y]"
2. Discuss with community: Get feedback, refine proposal
3. Implement in a branch
4. Submit pull request linking back to the issue
5. Community discussion and feedback
6. Revisions based on feedback
7. Approval and merge

### Major Changes (Fundamental challenge to principles, restructuring)

1. Open a discussion: "I'm proposing a major change to [X] because [Y]"
2. Deep engagement with community
3. Consideration of implications
4. Possible advisory council consultation
5. Documentation of the decision-making process
6. Implementation only after community consensus

## Community Standards

We operate on these principles:

### Intellectual Honesty
- Represent others' positions fairly before critiquing them
- Acknowledge valid points even if you disagree overall
- Update your position if presented with better evidence
- Admit when you don't know something

### Psychological Safety
- Assume good intent unless proven otherwise
- Separate people from ideas (critique ideas, not people)
- Welcome new contributors; help them understand norms
- No shaming or public humiliation

### Accountability
- Stand behind what you say (use your real identity)
- Acknowledge mistakes quickly
- Engage with criticism rather than dismissing it
- Follow through on commitments

### Inclusion
- Welcome contributors from all backgrounds
- Don't assume expertise means you understand this specific context
- Actively invite input from those who might see blind spots
- Make space for voices different from your own

## Conflict Resolution

**If you disagree with feedback:**

1. Assume misunderstanding first: "I think I'm misunderstanding. Can you clarify?"
2. Propose alternative: "What if we framed it this way instead?"
3. Seek common ground: "We agree on [X]; the disagreement is about [Y]"
4. Accept that some disagreements won't resolve: Document them and move forward

**If there's significant community disagreement:**

1. Advisory council is consulted
2. Both perspectives are documented
3. Decision is made based on framework coherence + community input
4. Minority perspective is preserved (noted in documentation)
5. Everyone commits to next phase regardless

**If there's interpersonal conflict:**

1. Take it to DMs; don't escalate in public forum
2. Seek to understand the other person's perspective
3. If unresolved, ask a neutral community member to mediate
4. If still unresolved, advisory council provides guidance

## Getting Started

**First time contributing?**

1. Read the core documentation: `docs/01-AL-HAQQ-PRINCIPLE.md`, `docs/02-INVERTED-PYRAMID-METHODOLOGY.md`, `docs/03-ICAM-COLLABORATIVE-INTELLIGENCE.md`
2. Read this document (you're reading it!)
3. Explore existing issues and discussions
4. Start small: Suggest a clarification, add a case study, or raise a question
5. Introduce yourself: "Hi, I'm [name], I'm interested in [aspect], here's my first contribution"

**What if you want to help but don't know how?**

1. Open a discussion: "I want to contribute but I'm not sure what's most valuable. I have skills in [X]. Where could I help?"
2. Community will respond with opportunities
3. We'll guide you toward work that aligns with your strengths
